## 3. Interview stages (no official stage list published; all reported unless noted)

Sources disagree on round counts, from 4–6 rounds to 6–9 [S12][S13][S16]. Timelines run about 3–6 weeks [S10][S11][S13]. The most consistent pattern across sources:

**Stage 0: Application with a "Why Anthropic?" written answer** (reported [S13]). Write the first draft yourself; you may refine it with Claude (confirmed [S9]).
- Method: give 2–3 specific reasons that tie to the RSP and Core Views (section 5) and to deploying Claude safely in industrial settings.

**Stage 1: Recruiter screen, ~30 min** (reported [S12][S16])
- Tests: motivation, role fit, logistics, mission alignment.
- Reported examples: on Glassdoor, a hiring-manager call asked why the candidate wanted to join and their views on Anthropic's research papers, and one candidate was asked whether they'd be fine if the stock went to zero (reported [S10]).
- Method: a 90-second pitch: 10+ years customer-facing in industrial equipment (CH/CN/US), then solo-built an internal AI platform in production. Prepare views on 1–2 Anthropic papers or posts.

**Stage 2: Hiring-manager or technical conversation** (reported [S12][S10])
- Tests: depth on LLM systems you have built, tradeoffs, customer judgment.
- Method: a project deep dive in STAR form. Situation, then Task, then Action (architecture: Claude tool use, batches, web search, MCP server, n8n, Supabase, Teams, approvals, audit logs), then Result (adoption metrics, error rates, cost). Be ready for "what would you do differently."

**Stage 3: Take-home, typically build plus presentation** (reported [S12][S13])
- Reported format: build a small Claude-powered app against a fictional customer brief, ~3–4 h, often a one-week window [S13]. The virtual onsite then includes a live demo and a presentation of the take-home [S12].
- **No AI unless told otherwise (confirmed [S9]).**
- Method for the technical presentation:
  1. Customer problem and success criteria.
  2. Architecture diagram.
  3. Prompt and tool design.
  4. Evals, with numbers.
  5. Failure modes and guardrails.
  6. Cost and latency (caching, batches, model choice).
  7. What you would do next with the customer.
- Leave Q&A time. State your assumptions explicitly.

**Stage 4: Customer-conversation / discovery simulation** (reported, single vendor source [S13], role-play with a skeptical stakeholder)
- Tests: discovery, listening, handling objections, not over-promising.
- Discovery-call structure:
  1. Agenda and confirm attendees and roles.
  2. Business context and KPIs.
  3. Current process and pain, quantified.
  4. Data: sources, sensitivity, residency, access.
  5. Constraints: security, compliance (ZDR, regional data), procurement, IT integration (SSO, Teams, ERP/CRM).
  6. Success criteria and eval set ownership.
  7. Stakeholders and decision process.
  8. Agree a scoped pilot and next steps.
- Recap in writing.

**Stage 5: Solution / system design for an enterprise LLM deployment** (reported [S12][S16])
- Reported themes (Dataford, unverified): secure API integration with enterprise legacy systems, and an enterprise knowledge-retrieval engine with role-based access control [S12]. Nora says focus falls on structuring the problem, explaining tradeoffs, and AI safety and deployment risk [S16]. Another guide says the emphasis is increasingly on evaluation harnesses over RAG architecture [S13].
- Structure, in order:
  1. **Requirements:** users, tasks, volume, latency, accuracy bar, data sensitivity.
  2. **Architecture:** workflow vs. agent [B1]; model tiering (Haiku for routing, Sonnet/Opus for reasoning) [D1]; RAG with contextual retrieval and citations [B4]; tools and MCP [B3].
  3. **Evals:** success criteria, golden set, graders (code, LLM, human), regression [B2].
  4. **Guardrails:** hallucination reduction, prompt-injection mitigation, structured outputs (section 4).
  5. **Human checkpoints:** approval gates for irreversible actions, escalation.
  6. **Security:** identity-backed keys or WIF, no browser keys [D4], RBAC on retrieval, audit logs, ZDR and data retention.
  7. **Rollout:** pilot, then shadow mode, then staged launch; monitoring, cost controls, feedback loop.

**Stage 6: Values / culture interview** (reported [S12][S14][S10])
- Tests: mission alignment and safety reasoning. Several guides call this the round where many rejections happen [S12]. A Blind reply says candidates are expected to discuss the mission [S14]. A Glassdoor candidate described the culture interview negatively [S10].
- Method: STAR stories on these themes:
  - Telling a customer "no" or "not yet" for safety or quality reasons.
  - Handling an ambiguous ethical tradeoff.
  - Admitting and fixing a mistake.
- Connect each to the RSP and Core Views [B5][B6].

**Candidate experiences:**
- One NYC SA report describes 2–3 weeks with minimal feedback between rounds (reported [S11]).
- Glassdoor SA reports are few (~5) and skew negative (reported [S10]).

## 4. Domain knowledge commonly tested (official links)

  - Principles: keep it simple, make planning visible, invest in the agent-computer interface.

  - Citations: https://platform.claude.com/docs/en/build-with-claude/citations.md
  - Search results: https://platform.claude.com/docs/en/build-with-claude/search-results.md

## 5. Anthropic candidate AI guidance, RSP, Core Views (brief; covered in depth elsewhere)

- **Candidate AI guidance** (confirmed [S9], updated 2025-07-10):
  - Draft application answers yourself, then refine them with Claude.
  - Take-homes are done without Claude unless Anthropic indicates otherwise.
  - Live interviews: "This is all you–no AI assistance unless we indicate otherwise."
  - Using AI to prepare is encouraged.
- **RSP** (confirmed [B5]): current version 3.4, effective 2026-07-08.
  - Capability thresholds trigger stronger ASL safeguards.
  - The ASL-3 deployment standard is defense in depth: access controls, real-time classifiers, async monitoring, jailbreak rapid response.
  - PDF: https://www-cdn.anthropic.com/files/4zrzovbb/website/0bacdc8440ea96e62a8766d99ebe1d4eea6d5f3a.pdf
- **Core Views on AI Safety** (confirmed [B6], 2023-03-08): transformative AI may arrive within about a decade, and no one yet knows how to reliably make it safe. Anthropic therefore takes a portfolio approach to empirical safety research across optimistic, intermediate and pessimistic scenarios.

## API facts (for the app)

All confirmed from official docs, fetched 2026-11-05.

**Current model IDs** ([D1], Claude API ID = alias for all four; dateless pinned snapshots):

| Model | Claude API ID | Notes |
|---|---|---|
| Claude Fable 5.1 | `claude-fable-5-1` | demanding reasoning / long-horizon agentic; $10/$50 per MTok |
| Claude Opus 5.5 | `claude-opus-5-5` | recommended starting point "for most workloads"; $4/$20 |
| Claude Sonnet 5.5 | `claude-sonnet-5-5` | speed and intelligence balance; $2/$10 |
| Claude Haiku 5.5 | `claude-haiku-5-5` | high-volume, low-latency; from $0.10/$0.50 |

- All four have a 1M context window and 128K max output [D1].
- Legacy models that are still available: Fable 5, Opus 5, Opus 4.8, 4.7, 4.6, 4.5, Sonnet 5, Sonnet 4.6, Haiku 4.5 [D1].
- Bedrock IDs are prefixed `anthropic.`, e.g. `anthropic.claude-opus-5-5` [D1].

**Required request headers** ([D2], [D4]):
- `x-api-key: <key>`: still supported, but documented as the **legacy fallback**. The primary form is `Authorization: Bearer <key>`; one of the two is required.
- `anthropic-version`: required.
  - Docs' current example and latest version: `2026-10-21` [D2][D3].
  - `2023-06-01` remains listed in the version history [D3]. Anthropic "recommends using the latest API version."
  - **Breaking in 2026-10-21:** `temperature`, `top_p` and `top_k` are removed and return a 400 error [D3]. The app must not send them if it uses that version.
- `content-type: application/json`: required.
- `anthropic-workspace-id`: required only when the API key isn't scoped to a workspace [D2][D4].

**Browser (CORS) access** ([D4], confirmed):
- A direct browser request must include **`anthropic-dangerous-direct-browser-access: true`**. The TypeScript SDK sends it when `dangerouslyAllowBrowser: true` is set [D5].
- Orgs with ZDR or the Compliance API enabled (including orgs that inherit it from a Claude Enterprise parent) cannot call the API from a browser at all. They get a 401 `authentication_error` beginning "CORS requests are not allowed for this Organization" [D4].
- Docs recommend calling the API from a back end. Browser access is acceptable only for trusted internal tools or short-lived dev keys [D5].

```js
fetch("https://api.anthropic.com/v1/messages", { method: "POST", headers: {
  "x-api-key": KEY, "anthropic-version": "2026-10-21", "content-type": "application/json",
  "anthropic-dangerous-direct-browser-access": "true" },
  body: JSON.stringify({ model: "claude-opus-5-5", max_tokens: 1024,
    messages: [{ role: "user", content: "Hello" }] }) });
```

## Illustrative (not reported): practice prompts

These were written for practice. **No candidate reported them.**

1. Discovery role-play: a plant-operations VP at a European machinery maker wants "AI for field service" but IT security is skeptical. Run 20 minutes of discovery.
2. Design: a technician copilot over service manuals, ERP work orders and sensor logs. It must cover RBAC, multilingual support (DE/ZH/EN), citations, offline sites, and human approval before parts orders.
3. Eval design: define success metrics and a 50-case golden set for warranty-claim triage, and explain how you would calibrate an LLM grader.
4. Cost: 2M documents per month to classify and extract. Choose model(s) and use batches and caching, then estimate the cost.
5. Objection: "Our data can't leave the EU / we need ZDR." Walk through deployment options (cloud platforms, retention settings) [D2][D4].
6. STAR: describe the approvals and audit-log design in your internal platform, and a time it caught a bad action.
7. Values: a customer asks you to deploy an agent with unrestricted write access to production systems. What do you do?

**Mapping the candidate's strengths:**
- Customer discovery: industrial customers in CH/CN/US.
- Production LLM systems: tool use, batches, web search, MCP, research agents.
- Guardrails: approvals, audit logs, human-in-the-loop.
- Adoption: rollout via Teams to non-technical staff.
